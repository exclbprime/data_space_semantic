# C 组语义互操作任务清单

C 组负责把设计提案中的欧洲数据空间互操作目标落实为可审查、可验证的 TIDE 语义规范。以下按依赖顺序组织。第 1–2 周以任务 1–4 的初版为目标，后续结合项目总计划推进任务 5–8。P1 是首个验证实例，P2–P4 和第二领域资源用于检验规范的覆盖范围。

组员或 AI 可整理资料、起草映射、实现规则并运行验证。每项的勾选由组长根据交付物和实际证据完成。涉及外部接入要求、业务事实或跨组承诺时，附对应负责人的确认记录。

## 第一阶段  确定语义基线与初版规范

- [ ] **1. 确认欧洲协同目标和候选规范。** 对照提案第 2.3、7.2 节和可视化报告的互操作性、目录设计，将 DSSC、IDSA、EOSC 和 DCAT/DCAT-AP 分别对应到具体需求。向项目负责人确认是否已有明确对接方、目录或交换场景。**交付**为一页规范基线表，记录规范及版本、引用条款、适用范围、对接方要求和待确认项。**组长核对**采用哪个 DCAT/DCAT-AP 版本作为试验基线，如何处理报告中的 DCAT 2.0 表述，以及哪些要求已由对接方确认。

- [ ] **2. 定义场景要支持的语义判断。** 选 P1 走通“发现资源 → 理解内容与使用条件 → 确认获取方式及版本”，并用 P2 对照“发现服务 → 理解能力和输入输出”。列出外部消费者需要回答的问题，例如谁发布、谁持有权利、可获取的是哪个文件版本，以及服务是否暴露原始记录。**交付**为一张问题与资源关系表。**组长核对**本地业务含义由谁确认，哪些描述允许对外展示，以及目录信息、使用条款与实际授权各由谁维护。

- [ ] **3. 审查本地模型与标准词汇的映射。** 对照场景包的 `metadata/context.jsonld` 和 P1/P2 描述，逐项标出直接复用、需转换、TIDE 扩展或待确认。先处理数据集、分发、服务、发布者、权利人、许可、版本和获取方式。**交付**为映射表，记录概念含义、标准 IRI、值类型、转换规则、来源和扩展理由。**组长核对**标准术语与本地事实是否等义。尤其检查 `owner` 是否混合不同角色、`license_or_terms` 是否需要拆分、`checksum` 指向哪个具体产物。

- [ ] **4. 起草并评审 P1 最小应用规范。** 基于选定基线描述研究数据集及对应的分发，将通用目录信息、工业领域字段和内部业务字段分别落实到相应模型。明确标识符、命名空间、字段约束、值域、版本和对外发布范围。**交付**为可供评审的应用规范、一个 P1 JSON-LD 示例及对应 RDF 表达，并记录首次 Semantic Treehouse 建模或导入尝试。**组长核对**每个新增限制和本地扩展都有场景依据，A 组知道如何映射目录，D 组知道按什么规则验证。工具尝试附环境、版本、输入和可复查结果。

## 后续阶段  验证、扩展与维护

- [ ] **5. 形成可复查的模型与校验规则。** 在实际 Semantic Treehouse 实例中维护模型版本，保存导出或转换结果，注明手工补写部分。明确 JSON Schema、SHACL 和业务检查各自负责的判断。**交付**为模型、规则、正反例和验证报告。**组长核对**一份合法描述可通过，缺权利人、缺来源和非法访问级别各有明确预期及实际结果，文件校验和由实际字节复核。

- [ ] **6. 验证外部消费者能读懂 P1。** 与 A、D 组核对实际目录发布结果，使用独立工具或测试消费者读取标准字段，并回答任务 2 的资源发现问题。按选定版本执行相应应用规范检查，记录缺项和未映射信息。有明确欧洲对接方时，用其接受的工具、目录或流程再验证。**交付**为目录样例、验证报告与消费结果。**组长核对**分别记录本地规则通过、选定规范通过、外部系统消费成功和对接方确认的证据。没有伙伴测试时将结果记录为本地互操作验证。

- [ ] **7. 用 P2–P4 和本届数据检验规范。** 明确 P2 服务、P3 请求和 P4 结果的对象含义及关联。与 A 组固定评测输入、时间拆分、字段和单位、输出边界及来源引用。准备本届 P1/P2 生成规则、字典、产品版本和校验和。固定输入、版本和环境运行两次，比较指标与样本数。**交付**为 P2–P4 映射、数据清单和带来源引用的两次实际结果。**组长核对**服务描述与受限数据的校验和所指对象、训练统计来源、标签与特征、复跑差异，以及结果能否追溯到精确输入和算法版本。

- [ ] **8. 验证模型变更和跨领域复用。** 保留 v1，设计一项 v2 变更并验证旧新输入的迁移或拒绝。选择一个第二领域资源，通过同一通用核心描述，交 D 组准入和 A 组交换。**交付**为模型变更记录、兼容验证、第二领域正反例及交换证据。**组长核对**哪些约定跨领域仍成立，领域差异是否由扩展表达，以及谁负责发布、通知和维护后续版本。
