# C 组语义互操作实施与验收说明

C 组负责资源模型、字段映射、校验规则和本届合成数据。A 组负责目录发布、Connector 交换和评测服务。B 组负责身份与授权判定，具体访问由资源负责人审批。D 组负责独立校验、发布准入和全链验证。跨组决定及待确认项记录在[跨组待议](../../跨组待议.md)。

阶段任务、进度及证据统一登记在[C 组语义互操作任务清单](TIDE_C_Group_Semantic_Task_List.md)。以下步骤供准备交付物和复核结果时查阅。初版描述、数据复核与规则盘点可以并行。先确定实际交付文件，再回填描述和哈希，最后用同版规则验证并交接。

## 1. 第 1–2 周：P1 初版与跨组交接

**阶段结果**　沿用场景包已有的 P1 数据定义、字段、单位和生成规则，基于现有描述和数据准备一份同版交接快照。到第 2 周末，A 能据此准备目录映射与文件接入，D 能独立复跑规则并核验快照。真实发布和传输在阶段 2 验收。

### 1.1 P1 描述、交付物、版本与哈希一一对应

**结果范围**　交付一份 P1 发布清单及其引用的资源描述、实际文件、字典和条款。以场景包的 P1 JSON-LD、CSV、生成器、字典和数据清单为起点。

- **1.1.1 核对资源和交付范围。** 按已有数据定义列出 P1 可交付文件，由 A 确认交付 CSV 还是资源包。若交付整包，列出包内文件及字典、研究说明的位置。将确认结果写入资源描述。
- **1.1.2 核对标识和版本。** 记录 `resource_id`、RDF `@id`、`product_version` 和 `schema_version` 各自标识什么。A 确认 Asset 怎样引用描述和交付物。产品升级若涉及 Asset 或已有 Grant，由 A、B、C 共同确认处理方式。
- **1.1.3 复核已有 P1 数据。** 在工作副本中复跑现有生成器，记录环境、生成器版本、种子、行数和复跑哈希。按现有字典核对 CSV 字段和单位。
- **1.1.4 冻结交接文件和清单。** 按最终文件的实际字节重算 SHA-256，记录文件与产品版本的关系，同步更新描述中的引用。场景包当前的 `checksum` 对应 `p1-process.csv`。若交付整包，分别标明整包与 CSV 的核对对象和哈希。

**验收标准**　从 P1 描述能定位到唯一的产品版本、规则版本和实际交付物。清单列明文件名、校验对象和预期值，重算 SHA-256 一致。CSV 至少 2,000 行，字段和单位与字典一致，固定生成条件下复跑的行数及 CSV 哈希一致。

### 1.2 P1 目录映射和本地验收规则可用

**结果范围**　交付 P1 目录映射与白名单、目录示例、核心模型与工业扩展初稿、合法 P1 JSON-LD/RDF、JSON Schema、SHACL 和正反例。

- **1.2.1 交付目录映射和描述。** 写清字段含义、值类型和转换方式，提交目录示例及同版 P1 JSON-LD/RDF。资源负责人确认发布者、权利人、条款和展示范围，A 确认 Asset 映射与获取方式。记录选定的 DCAT/DCAT-AP 试验版本和报告中 DCAT 2.0 的处理。外部对接约定由项目负责人确认。
- **1.2.2 核对模型和规则。** 对照场景包已有的模型、JSON Schema 和 SHACL，记录结构、RDF 和业务检查各自覆盖的约束。按 1.1 的描述和实际交付物确定版本与哈希检查的输入。
- **1.2.3 运行本地正反例。** 用合法 P1 及缺权利人、缺来源、非法访问级别三个反例验证规则。交付逐例预期、实际结果、错误路径和复跑步骤。
- **1.2.4 尝试在 Semantic Treehouse 建模或导入。** 确认实例、权限和操作人，记录实际环境、输入、模型标识或操作结果。工具正式验收见 2.1。

**验收标准**　映射与目录示例覆盖已确认的字段白名单，示例与 1.1 的版本和获取方式一致。缺权利人、缺来源、非法访问级别分别触发预期规则，合法样例通过。保存运行结果，并确认 RDF 校验确实检查了目标资源节点。涉及展示的未决字段记录待核对的依据和影响，确认后纳入白名单。

### 1.3 A、D 两组分别验收同版交接包

**结果范围**　C 提供一个交接入口，引用 1.1 和 1.2 的产物，并标明同一份 P1 的资源 ID、产品版本、规则版本和清单版本。

- **1.3.1 汇总并检查交接材料。** 收齐 1.1 和 1.2 的产物，建立交接索引。逐项确认 A、D 使用的是同一份资源描述、实际文件和清单，规则报告引用的是随包提交的规则版本。
- **1.3.2 向 A 交接发布与接入材料。** 提供合法的 P1 JSON-LD、目录示例、Asset/目录映射、展示白名单、获取方式和版本约定。同时提供实际交付物、字典、条款引用和 SHA-256 清单。**A 组验收**时走查发布字段、版本、用户收到的文件与校验对象，重算交接文件哈希并记录结果。
- **1.3.3 向 D 交接校验材料。** 提供同版 JSON-LD/RDF、JSON Schema、SHACL、业务检查说明、正反例、逐例预期和复跑步骤，随附实际文件和 SHA-256 清单。**D 组验收**时独立复跑，记录合法样例通过和三个反例的失败路径，核对实际文件、描述及清单中的版本和哈希，保留报告。

**验收标准**　A、D 各留一条核对记录，所引用的资源 ID、产品版本和规则版本能对上同一个交接入口。发现差异时记录受影响的产物和待修正项，改动后复核受影响的检查。

## 2. 第 3–6 周：P1 真实发布、目录消费和交换

### 2.1 可复查的模型版本与发布准入

**结果范围**　交付实际 Semantic Treehouse 模型及版本、规则产物和 D 组准入报告。对应 TC01、TC05。

- **2.1.1 保存实际模型和规则来源。** 在 Semantic Treehouse 维护评审过的模型，核对导出或转换结果及手工补写项，给 A、D 同一版本。
- **2.1.2 核对实际准入。** D 在实际校验环境复跑正反例，把错误路径对应到具体规则，A 核对发布入口使用的规则版本与准入结果。

**验收标准**　模型版本、导出或转换产物及手工补写记录可复查。合法 P1 经准入可发布，反例触发指定错误且无法发布。

### 2.2 可消费的目录与真实 P1 交换

**结果范围**　交付实际目录样例、规范检查和独立消费证据，以及 EDC 原生传输和接收端哈希。对应 TC04。

- **2.2.1 验证目录。** A 提供实际发布内容，按选定规范版本检查目录 RDF 并注明导出和验证范围。独立消费者能找到 P1 并读出发布者、条款、获取方式和版本。项目负责人确认有明确欧洲伙伴时，再按其目录或工具验证并保存确认记录。
- **2.2.2 验证传输。** A 在实际授权后完成原生交换，B 提供授权判定，D 记录流程证据。按 1.1 的清单核对接收端产物、版本和哈希，并汇总目录与传输证据。

**验收标准**　实际目录符合展示白名单，记录规范检查范围与消费结果。原生传输记录与接收产物可关联，接收端 SHA-256 与该产品版本清单一致。

## 3. 第 7–8 周：P2–P4 评测语义与复现

### 3.1 可重建的 P2 输入与可验证的 P3/P4 规则

**结果范围**　交付 P2 数据及清单、服务与数据的版本关系、P3 请求规则、P4 输出与来源规则。对应 TC05、TC06。

- **3.1.1 制备 P2 数据。** 交付至少 2,000 行合成数据，种子和工况独立于 P1。受限 CSV 供提供方内部评测。分别记录服务说明与 CSV 的版本及 SHA-256，并验证数据可重建。
- **3.1.2 固定评测口径。** 与 A 组确定 P1 是计算输入还是来源引用，并记录训练与测试数据、时间切分、预处理顺序、有效样本口径、Recipe 哈希与算法版本。按确认后的数据版本准备规则和用例。
- **3.1.3 交付 P3/P4 规则。** 根据 3.1.2 维护 P3 请求、P4 输出及来源的规则和正反例，逐项核对字段含义和单位。A 将约定接到实际服务。
- **3.1.4 验证实际输入和输出。** 与 D 用参数、单位或版本反例验证拒绝或约定转换，检查 P4 出口范围。核对 `target_temp` 仅作标签、跨切分边界的训练标签被排除、预处理统计只取训练段。

**验收标准**　P2 数据可重建，服务说明和受限数据可分别核验。合法 P3 在实际服务产生符合规则的 P4。反例按预期拒绝或明确转换，消费者出口只含获准的汇总与来源信息。

### 3.2 两次真实评测结果可复查

**结果范围**　交付两次真实作业的结果对照和来源证据。对应 TC08。

- **3.2.1 固定输入并对照两次作业。** 与 A 固定数据、P3、算法代码、规则和环境，确认 MAE 容差。取得 A 两次真实运行的结果，记录作业 ID、MAE、样本数，以及数据、请求和算法版本或哈希。
- **3.2.2 验证来源与复查。** 从两份 P4 定位各自的精确输入和算法版本，用数据清单复核版本和哈希。B、D 配合复查者用独立授权领取并验证结果。

**验收标准**　两个作业 ID 各有实际执行记录，样本数一致，MAE 差在约定容差内。任务书的候选容差为 `1e-9`。复查者可在获准范围内核对两次结果的来源。

## 4. 版本演进与第二领域复用

### 4.1 v1/v2 兼容行为可验证

**结果范围**　交付双版本规则、样例、差异记录及迁移或拒绝条件。对应 TC05，配合语义联调。

- **4.1.1 实现一项有场景依据的变更。** 保留 v1，交付 v2、规则差异及旧、新输入的预期结果。
- **4.1.2 验证版本选择及转换。** A 接入版本检查或约定转换，D 逐个验证旧、新输入与规则的组合，逐项核对预期与实际结果。

**验收标准**　双版本均可复查。支持的迁移产生明确的目标版本与字段值，不兼容输入给出具体拒绝原因。

### 4.2 第二领域资源可准入、可交换

**结果范围**　交付一个第二领域模拟资源、其扩展规则和真实交换证据。对应 TC11，配合第 9–10 周集成。

- **4.2.1 实现第二领域扩展。** 沿用同一通用核心，交付领域扩展和资源描述。提供合法与错误样例，附上实际文件、版本和哈希清单。
- **4.2.2 核对准入和交换证据。** D 验证准入正反例，A 使用现有 Connector 核心交换合法资源，按清单核对接收文件和版本，并关联准入报告及传输记录。

**验收标准**　合法资源通过准入且接收端哈希匹配，非法扩展或缺少核心字段被拒绝。保留规则差异、原生传输记录和验证报告。
